# middleware

Void のミドルウェアを置くフォルダ。ここのファイルは、どのリクエストでも動く。

## 今あるもの

| ファイル    | すること                              |
| ----------- | ------------------------------------- |
| `01.rpc.ts` | `/rpc` の下のリクエストを oRPC に渡す |

## ファイル名

Void が、ファイル名を見て動かす順番を決める。

- `<数字>.<名前>.ts` と書く（`01.rpc.ts`）。先頭の数字が小さい順に動く
- 数字を付けないファイルは、いちばん最後に動く
- このフォルダの下にある `.ts`・`.js` のファイルは、サブフォルダの中まで、全部ミドルウェアとして読まれる。名前が `_` から始まるものだけは読まれない

## 注意

- ミドルウェアでないファイル（共通の処理・テスト）を、ここに置かない。置くと、ミドルウェアとして読まれる
  - 処理の中身は `src/server/rpc/` などに書き、ここからは呼ぶだけにする
- どのリクエストでも動くので、関係のないパスは、最初に `next()` へ渡す
- ルート（`routes/`）と違い、メソッドで絞られない。`HEAD` や `OPTIONS` も届くので、受けるメソッドは自分で絞る
  - `/rpc` は、`src/server/rpc/handler.ts` が契約で使うメソッドだけを受ける
- ミドルウェアを足すときは、順番を決めて数字を付ける。前に入れたいものができたら、数字を振り直す
