# 単体テスト

記録日: 2026-11-08 / 対象: Vite+ 1.5.0（Vitest 5.1.0）、jsdom 31.0.0、Void 1.6.2、tsrs 0.22.0-ts7.1.0-beta

`apps/web` に、単体テストだけを入れた。部品を描いて確かめるテスト（コンポーネントのテスト）は入れない。

```zsh
vp run test          # client と server の両方
vp run test:client   # src/client だけ
vp run test:server   # src/server だけ
```

コマンドはルートで実行する。ルートの組み込みの `vp test` は使わない（下の「ルートの vp test では動かさない」）。

## client と server で、動かす環境を分ける

| プロジェクト | 対象                                         | 環境  | 理由                                                 |
| ------------ | -------------------------------------------- | ----- | ---------------------------------------------------- |
| `client`     | `src/client/**/__tests__/**/*.test.{ts,tsx}` | jsdom | ブラウザで動くコード。DOM と `localStorage` を真似る |
| `server`     | `src/server/**/__tests__/**/*.test.ts`       | Node  | Worker で動くコード。DOM を持たない                  |

`apps/web/vite.config.ts` の `test.projects` に 2 つ書いた。`server` を DOM のない環境で動かすので、BE のコードがうっかり `window` や `document` を使うと、テストで気づける。

jsdom を選んだ理由は design-system-prac の docs/16 と同じ。本物のブラウザ（ブラウザモード）より速く、準備もパッケージを入れるだけで済む。Kotlin + Spring で言えば、jsdom は MockMvc に近い。

`server` は Node で動かすので、Workers にしかない API（D1 のバインディングなど）は動かない。それを使うコードを確かめるには、Cloudflare の Workers の上でテストを動かす仕組み（`@cloudflare/vitest-pool-workers`）が要る。単体テストの範囲を超えるので、今は入れない。

### Void の plugin を引き継ぐ

どちらのプロジェクトも `extends: true` で、`vite.config.ts` の `plugins` を引き継ぐ。`@schema` などは Void の plugin が解決するので、BE のコードを読むテストに要る。Void の plugin を読んでも、テストは壊れなかった。

### 試しのテスト

`src/client/__tests__/environment.test.ts` と `src/server/__tests__/environment.test.ts` に、それぞれの環境の設定が効いていることを確かめるテストを置いた。Vitest はテストが 0 個だと失敗するので、本物のテストができる前から `vp run test` が通るようにするためでもある。環境の設定を間違えたときに気づく見張りにもなる。

## describe・test・expect を import せずに使う

design-system-prac と同じく `globals: true` にした。型は自動では付かないので、`vite-plus/test/globals` を `types` に足す。アプリのコードには足さず、テストのファイルにだけ読ませるため、tsconfig を分けた。

```text
apps/web/
├── tsconfig.json        … 下の 2 つを指すだけ（files: []）。エディタが、ファイルごとにどちらで見るかを見つける
├── tsconfig.app.json    … アプリのコード。src/**/__tests__ は exclude で外す
└── tsconfig.test.json   … src/**/__tests__ だけ。app を extends して、types に vite-plus/test/globals を足す
```

- 型チェック（`typecheck`）は `tsrs --noEmit -p tsconfig.app.json && tsrs --noEmit -p tsconfig.test.json`。tsrs には `-b`（参照でつないだ tsconfig をまとめて見る）がないので、1 つずつ見る
- `tsconfig.test.json` の `exclude: []` は、`tsconfig.app.json` の `exclude`（`__tests__` を外す）を引き継がないため
- `tsconfig.app.json` は `.void/tsconfig.json` を extends する。`paths`（`void/db`・`@schema`）を書かないのは前と同じ
- dependency-cruiser は `paths` を読むために `tsconfig.app.json` を指す。`tsconfig.json` は `files: []` なので、`paths` がない
- `void prepare` は、分けた tsconfig を書き換えなかった

## テストの置き場所

確かめるファイルと同じ階層に `__tests__/` を作り、その中に `<名前>.test.ts` で置く。design-system-prac と同じ。

`__tests__/` の外に置いてはいけない理由が、このリポジトリにはもう 1 つある。Void は `src/server/routes/` の下のファイルを API のルートにするので、`src/server/routes/b.test.ts` を置くと `/b.test` というルートになり、本番にも公開される。`_` で始まるフォルダは Void がルートにしないので、`__tests__/` の中なら大丈夫。

| 置いた場所                                  | 結果                                                         |
| ------------------------------------------- | ------------------------------------------------------------ |
| `src/server/routes/b.test.ts`               | Void が `/b.test` のルートにした                             |
| `src/server/routes/rpc/__tests__/a.test.ts` | ルートにならない                                             |
| `src/client/routes/d.test.ts`               | TanStack Router が「Route を export していない」と警告を出す |
| `src/client/routes/__tests__/c.test.ts`     | 同じ警告。`routeFileIgnorePattern: "__tests__"` で消した     |

## 道具で守る

| わざと入れた間違い                                      | 止めたもの                                                                   |
| ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `__tests__/` の外にテスト（`src/client/stray.test.ts`） | `typecheck` と `vp check`（`TS2593`・`TS2304`。`test`・`expect` の型がない） |
| Void の `routes/` の中に、`__tests__/` の外のテスト     | 同上。コミットで止まるので、ルートとして公開される前に気づける               |
| アプリのコードで `expect`（import なし）                | `typecheck` と `vp check`（`TS2304`）                                        |
| アプリのコードで `vite-plus/test` を import             | `vp run lint:deps`（`no-test-runner-in-app`）                                |
| テストの中の型エラー                                    | `typecheck` と `vp check`（`TS2322`。`tsconfig.test.json` が読まれている）   |
| 失敗するテスト                                          | `vp run test`                                                                |

`__tests__/` の外のテストは `vp run test` では動かない（`include` に入らない）。動かないことに気づけないと困るので、型チェックで止まるようにした（design-system-prac の docs/16 と同じ）。

`no-test-runner-in-app` は、`globals: true` でも `import { vi } from "vite-plus/test"` のように import することがあるため。アプリのコードに入ると、テストの道具がバンドルに入る。

テストのファイルは本番のビルドに入らなかった（アプリのコードから import されないため）。

## ルートの vp test では動かさない

ルートで組み込みの `vp test` を打つと、2 つの困ったことが起きた。

| ルートの `vite.config.ts` の `test` | 起きたこと                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 書かない                            | `apps/web` の設定を読まず、すべての `*.test.ts` を Node で動かした。`client` のテストが `localStorage` がなくて失敗した |
| `projects: ["apps/web"]`            | テストは通ったが、ルートに `void.config.ts`・`.void/`・`.void-wrangler.jsonc` ができ、`.gitignore` に 1 行足された      |

2 つ目は、Void の plugin が今いる場所（`process.cwd()`）を自分のプロジェクトとみなすため。Void のソースにも「Resolve root relative to CWD」とあり、場所を指定するオプションもない。`vp run web#dev` や `vp run web#build` が大丈夫なのは、`vp run` がパッケージのフォルダに移ってから動かすから。

そこで、テストも `apps/web` の中で動かす。

- `apps/web/package.json` に `test`・`test:client`・`test:server` を置く（中身は `vp test`）
- ルートの `package.json` は、`vp run web#test` などで呼ぶだけ。`dev`・`build` と同じ形
- ルートの `vite.config.ts` は `test.include: []`。組み込みの `vp test` を打つと「No test files found」で止まり、間違った環境で動かすことも、ルートにファイルを作ることもない

ルートからだと、プロジェクトの名前が `web (client)` のように、パッケージの名前付きになることも分かった（`--project "web (client)"` で選べる）。`apps/web` の中で動かすので、今は `--project client` で足りる。

## コミット時には動かさない

コミットの検査（整形・lint・依存の向き・型チェック）には入れなかった。テストは `vp run test` で動かし、あとで作る CI に任せる。テストが増えても、コミットは速いまま。

## テストの書き方の決まり

- 確かめるファイルと同じ階層に `__tests__/` を作り、`<名前>.test.ts` で置く。`src/client/routes/` には置かない（ルートのファイルには `Route` しか書かないので、確かめるものがない）
- `describe`・`test`・`expect`・`vi` は import しない
- `it` ではなく `test` を使う。名前は日本語で「〜こと」
- `vi.stubGlobal`・`vi.spyOn` で差し替えたものは、テストごとに自動で元に戻る（`unstubGlobals`・`restoreMocks`）
