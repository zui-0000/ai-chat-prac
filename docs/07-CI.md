# CI

記録日: 2026-11-14 / 対象: Vite+ 1.6.0、setup-vp 1.22.0、actions/checkout 7.0.1、gh-actions-lock 0.4.1、Node.js 26.13.1、pnpm 12.18.0

PR と main で、手元の確認（`CLAUDE.md` の作業のチェックリスト）と同じものを GitHub Actions で回す。
あわせて、ワークフローそのものを守る設定も入れる。

## 決めたこと

| 何を                        | どうしたか                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------- |
| ファイル                    | `.github/workflows/ci.yaml`（ワークフローは `CI`、ジョブは `check`）               |
| 動くとき                    | PR を作った・更新したとき、main に入ったとき                                       |
| Vite+ の入れ方              | `voidzero-dev/setup-vp`。Node.js・pnpm・`vp install`・キャッシュをまとめて受け持つ |
| Node.js の版                | 書かない。`devEngines.runtime` を読むので、手元と同じ版になる                      |
| ジョブの分け方              | 1 つのジョブで順に回す                                                             |
| テスト                      | client と server を、毎回両方回す（ステップは分ける）                              |
| Action の版                 | YAML にはタグ（`@v7.0.1`）を書き、コミットは `actions.lock` で固定する             |
| Action の版の更新           | Dependabot。週 1 回、公開から 1 日たった版だけ。`actions.lock` も一緒に更新される  |
| 権限                        | `contents: read` だけ。checkout のトークンも残さない                               |
| マージの条件                | `check` が通らないと、main にマージできない（ルールセット）                        |
| ワークフローを守る設定      | SHA で固定していない Action を止める設定と、CodeQL の Actions の解析を入れる       |
| `.github/` の YAML の拡張子 | `.yaml` にそろえる                                                                 |

## 回すもの

| ステップ                   | コマンド                       |
| -------------------------- | ------------------------------ |
| フォーマット・lint・型     | `vp check --continue-on-error` |
| 型チェック（各パッケージ） | `vp run typecheck`             |
| import の向き              | `vp run lint:deps`             |
| テスト（client）           | `vp run test:client`           |
| テスト（server）           | `vp run test:server`           |
| ビルド                     | `vp run build`                 |
| `actions.lock` の確認      | `gh actions-lock --verify`     |

- どれかが落ちても、残りは続けて回す。1 回の実行で全部の結果を見られる
- `vp check --continue-on-error`（Vite+ 1.6.0 から）は、フォーマット・lint・型のエラーをまとめて出す
- 依存は `--frozen-lockfile` で入れる。lockfile と `package.json` がずれていたら止まる

## 1 つのジョブで順に回す

時間のほとんどは `vp install` にかかる。ジョブを分けると、その数だけ install が増える。

**手放すもの**: ジョブを分けたときほど並べて速くはならない。遅くなったら分け方を考え直す。

## テストは毎回全部回す

差分のあるほうのテストだけを回す案（client の差分なら client、`packages/contract` の差分なら両方）もあったが、今は毎回全部回す。

**理由**:

- テストは数秒で終わる。飛ばしても浮く時間は 1〜2 秒
- 差分で決める一覧は人が書く。両方に効くファイルを足し忘れると、回すべきテストが飛ばされ、CI は緑のまま見逃す

差分で回すのは、Vite Task のキャッシュ（ZSCM-32）で実現する。Vite Task はタスクが実際に読んだファイルを記録するので、一覧を手で書かずに済む。
`packages/contract`・設定・依存が変わったら両方を回し、main に入ったときはいつも全部回す。

ワークフロー全体を `paths` で止めてはいけない。ジョブが動かないと、ルールセットが待つ `check` の結果が届かず、PR をマージできなくなる。

## Action のコミットは `actions.lock` で固定する

タグは後から付け替えられる。乗っ取られた Action のタグが書き換えられると、タグで書いたワークフローは書き換えられた中身を動かす。
GitHub の「ワークフローの依存の lockfile」（`.github/workflows/actions.lock`）で、使う Action をコミットに固定する。
npm で言えば、`package.json` に版を書き、`pnpm-lock.yaml` で中身を固定するのと同じ。

```yaml
# ci.yaml にはタグを書く
- uses: voidzero-dev/setup-vp@v1.22.0
```

```yaml
# actions.lock（gh actions-lock が作る。手で書かない）
'voidzero-dev/setup-vp@v1.22.0':
  ref: 'v1.22.0'
  commit: 'sha1-cab1ab9eaff52d4857875f4f2c016e36af8f2c76'
```

- 実行されるのは、lockfile に固定したコミット。名前の裏のリポジトリが、登録したときと同じかも確かめる
- Action の中で使われている Action まで固定する。YAML に SHA を書く方法では、ここまでは固定できない
- lockfile に無い Action をワークフローが使うと、ジョブが失敗する
- 「SHA で固定していない Action を止める設定」も、lockfile に入っていれば通る
- `setup-vp` の `v1` のタグは v1.15.0 で止まっていて、新しい版を受け取れない。版まで書く

### 決めるまでに比べたもの

| 案                                 | 決めたか   | 理由                                                               |
| ---------------------------------- | ---------- | ------------------------------------------------------------------ |
| SHA ＋ 版のコメント（`# v1.22.0`） |            | 動くが、YAML が読みにくい。Action の中の Action までは固定できない |
| SHA だけ                           |            | 版が分からず、Dependabot の更新の差分も読めない                    |
| **タグ ＋ `actions.lock`**         | これにした | YAML が読みやすく、中の Action まで固定できる                      |

**手放すもの**: `gh-actions-lock` はまだ 0.x（2026-04 にできた）。GitHub の docs にも、正式版かどうかが書かれていない。

### 使い方

```zsh
gh extension install github/gh-actions-lock --pin v0.4.1   # 初回だけ
gh actions-lock            # ワークフローを足した・Action を変えたあと。actions.lock を更新する
gh actions-lock --verify   # actions.lock がずれていないか確かめる（CI でも回す）
```

- `--pin` で拡張の版を固定する。v0.4.1 のリリースは、書き換えられない設定（immutable）になっている
- 拡張の版は Dependabot では上がらない。上げるときは、手元と `ci.yaml` の `--pin` をそろえて書き換える

### 版の更新は Dependabot に任せる

`.github/dependabot.yaml` で、Action の版を上げる PR を週 1 回作らせる。Dependabot は、Action を上げるときに `actions.lock` も同じ PR で作り直す。

- `cooldown.default-days: 1` で、公開から 1 日たった版だけにする。pnpm の `minimumReleaseAge`（1 日）とそろえる。書かないと 3 日
- コミットメッセージは `chore(deps): ...` にして、Conventional Commits にそろえる
- npm の依存は対象にしない。`vp` で上げる
- lockfile に登録していないワークフローは、Dependabot が登録してくれない。ワークフローを足したら、`gh actions-lock` を回す

## マージの条件とワークフローを守る設定

GitHub のリポジトリの設定で入れる（`gh` で設定する）。

| 設定                     | 何をするか                                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| ルールセット             | main へのマージに、`check` が通ることを求める                                                                                              |
| SHA の固定の強制         | SHA で固定していない Action を使うと、ワークフローが失敗する（Actions の設定の `sha_pinning_required`）。`actions.lock` に入っていれば通る |
| CodeQL の Actions の解析 | ワークフローの YAML を解析し、スクリプトの注入・信用できないコードの checkout・権限の付けすぎなどを見つける。公開リポジトリは無料          |

どれも AI ではなく、決まった規則で機械的に止める。ワークフローを足すたびに、最初からこの検査を通る。

## Vite Task のキャッシュは CI で使い回さない（今は）

Vite+ 1.6.0 でも、CI でキャッシュを使い回すのは試験的。それに、`package.json` のスクリプトは既定でキャッシュされない（`vp run` が「cache disabled」と出す）。
入れるときは ZSCM-32 で、入れる前と後の時間を比べる。この CI の時間が、比べる元になる。
