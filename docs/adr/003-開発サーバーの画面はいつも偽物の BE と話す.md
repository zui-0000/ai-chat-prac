# 003 開発サーバーの画面はいつも偽物の BE と話す

- 状態: 採用
- 日付: 2026-11-08

## 背景

`vp run dev` では本物の BE（workerd とローカルの D1）も立ち上がるが、画面を作るときに、失敗やストリーミングの途中などの状態を自由に出したい。

偽物を API ごとに生の MSW で書くと、oRPC の通信の形を手で真似ることになる。約束とずれても気づけず、「偽物では動くのに、本物で壊れる」が起きる。

## 決めたこと

- 開発サーバーの画面は、いつも偽物の BE と話す。本物は `vp run build` してから `vp run preview` で見る
- 画面の oRPC のクライアントは本物のまま、ブラウザの MSW の中で oRPC の受け口を動かして、BE の側を偽物にする。偽物も約束を `implement` する（ADR 002）。約束とずれると型エラーになる。偽物は `apps/web/src/client/mocks/` に置く
- 失敗などの状態は、URL の `?scenario=<API>.<状態>` で 1 つ選ぶ。単体テストでも同じシナリオを使う
- Service Worker のファイルは、MSW 3 の Vite の plugin が、入れた `msw` から配る。`public/` に置かず、コミットもしない
- 偽物は開発のときだけ動的 import で読み、本番のバンドルに入れない

## ほかの案

| 案                                       | 選ばなかった理由                                                                   |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| API ごとに生の MSW で書く                | 通信の形を手で真似ることになり、約束とずれても気づけない。ストリーミングも手で組む |
| `npx msw init` で `public/` にコピーする | コピーが古くなり、生成された数百行のファイルがリポジトリに入る                     |
| URL や環境変数で、偽物と本物を切り替える | どちらと話しているかが、画面によって変わる                                         |

## 手放すもの

- 開発サーバーの画面から、本物の BE は確かめられない
- 偽物の中でだけ、BE のライブラリ（`@orpc/server`）を読むのを許した
