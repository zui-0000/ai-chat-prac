# 001 土台に Void を使う

- 状態: 採用
- 日付: 2026-11-08

## 背景

いずれ Cloudflare で動かしたい。元にした design-system-prac では、FE（React）と BE（Hono を Bun で動かす）を別のアプリに分けていた。分けると、デプロイの設定・D1 などの用意・マイグレーションを、それぞれ手で書くことになる。

## 決めたこと

- Void を土台にする。1 つの Vite のプロジェクトに FE と BE を入れ、1 つの Cloudflare Worker としてデプロイする
- ツールチェーンは Vite+ にする（Void の既定）
- FE は `apps/web/src/client/`、BE は `apps/web/src/server/` に置く。Void が読むのは `src/server` の下だけにする（`sourceDir`）。`src` にすると `src/routes` が API のルートになり、TanStack Router とぶつかる

決め手:

- `void deploy` の 1 つで、ビルド・D1 などの用意・マイグレーション・アップロードまでする
- 使うリソースを import から推測するので、`wrangler.jsonc` を手で書かなくてよい
- Cloudflare のアカウントが無くても、workerd とローカルの D1 で、本番と同じランタイムで動く

## ほかの案

| 案                                            | 選ばなかった理由                                                   |
| --------------------------------------------- | ------------------------------------------------------------------ |
| FE と BE を別のアプリにする（前のリポジトリ） | デプロイ・リソース・マイグレーションの設定を、2 つ分持つことになる |

## 手放すもの

- BE を FE と別にデプロイ・スケールできない
- Void の作法に寄せることになる。Void の plugin は、今いるフォルダを自分のアプリとみなすので、テストや検査は `apps/web` の中で動かす
