# FE のフォルダ構成

記録日: 2026-11-18 / 対象: TanStack Router 1.170.46、TanStack Query 5.107.1、@orpc/tanstack-query 1.16.2、dependency-cruiser 18.7.2

`apps/web/src/client/` の直下に何を置くかと、フォルダどうしの import の向きを決めた。`components/` の中の分け方は `docs/06-デザインシステムを決める.md` の「置き場所」にある。

## 構成

```text
apps/web/src/client/
├── main.tsx           入口。開発のときに MSW を動かし、<App /> を描く
├── App.tsx            QueryClient とルーターを作り、Provider で包む
├── routeTree.gen.ts   TanStack Router が作る
├── routes/            TanStack Router のルート（Route だけを書く）
├── components/        部品（ui/・features/・layouts/・pages/）
├── hooks/             汎用の hooks。アプリの初期化でやる処理も use〜.ts で書く
├── stores/            zustand。UI の状態だけを持つ
├── api/               oRPC のクライアント（client.ts）と、コンテキストごとの TanStack Query の定義
├── utils/             純粋な汎用関数
├── assets/            画像と、lucide-react に無いアイコン
├── styles/            トークンと全体の CSS
├── mocks/             偽物の BE（MSW）
└── __setup__/         テストの準備
```

`src/client` の直下には、どこからでも使える汎用のものを置く。1 つの機能でしか使わないものは、`components/features/<機能>/` の中に一緒に置く（コロケーション）。

## 向き

```text
main.tsx → App.tsx → routes/ → components/ → hooks/ → stores/・api/ → utils/
```

左から右へだけ import する。`stores/` と `api/` は、お互いに読まない。`assets/`・`styles/` は部品から読む。

| ルール                      | 止めること                                                                                            |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| `client-entry-not-imported` | `main.tsx`・`App.tsx` をほかから読む（`main.tsx` だけは `App.tsx` を読める）                          |
| `components-not-to-routes`  | `components/` から `routes/` を読む                                                                   |
| `hooks-not-to-upper`        | `hooks/` から `components/`・`routes/` を読む                                                         |
| `stores-not-to-upper`       | `stores/` から `api/`・`hooks/`・`components/`・`routes/` を読む                                      |
| `api-not-to-upper`          | `api/` から `stores/`・`hooks/`・`components/`・`routes/` を読む                                      |
| `utils-pure`                | `utils/` から、ほかのフォルダや React とその仲間（TanStack の React 版・zustand・lucide-react）を読む |
| `mocks-not-to-client`       | 偽物の BE（`mocks/`）から、`src/client` のほかのフォルダを読む                                        |

テスト（`__tests__/`）は外した。テストは、確かめるものを組み立てるために上のフォルダを使うことがある。

わざと違反を置き、全部止まることを確かめた（上のルールごとに 1 つずつと、`utils/` から React・`@tanstack/react-query` を読む場合）。zustand と lucide-react は、まだ入っていないので確かめていない。入れたときに、`utils/` から読むと止まるかを確かめる。`hooks/` から `api/`、`utils/` の中どうし、テストから偽物の入口を読むのは通った。

## 決めたこと

### `main.tsx` と `App.tsx` を分ける

`main.tsx` には、React の外の準備（開発のときに MSW を動かす、`#root` に描く）だけを置く。`QueryClient`・ルーター・Provider は `App.tsx` に置く。

`main.tsx` は React の部品ではないので、hooks を呼べない。アプリの初期化でやる処理を `hooks/` に `use〜.ts` で書いたとき、呼ぶ場所が要る。

- Query もルーターも使わない hook は、`App.tsx` で呼ぶ
- Query やルーターを使う hook は、Provider の内側にある `RootLayout` で呼ぶ

### サーバーのデータは TanStack Query だけが持つ

API の応答は、TanStack Query のキャッシュにだけ置く。zustand のストアにコピーしない。コピーすると、同じデータが 2 か所にでき、どちらが新しいかを自分で合わせることになる。ストアには、開いているパネルや入力中の文字のような、UI の状態だけを置く。`stores-not-to-api` で止める。

### `api/` はコンテキストごとに分ける

`api/client.ts` に、oRPC のクライアント（`client`）と TanStack Query の道具（`orpc`）を置く。`orpc.message.list.queryOptions()` のように、約束からキーと取得の関数が作られる。

コンテキスト（約束の `message`・`chat`）に固有の定義（作ったあとに一覧を古くする、など）が要るようになったら、`api/message/` のように `mocks/api/` と同じ並びでフォルダを作る。まだ要らないので、今は `client.ts` だけ。

### OpenAPI からの生成（orval）は使わない

orval は、OpenAPI の定義から API のクライアントと TanStack Query の hooks を作る。このリポジトリは oRPC で、約束（`packages/contract`）の型を FE と BE が直接読むので、生成するものが無い。npm でいえば、型付きの API を共有パッケージから import するのと同じ。

### 部品からルートの情報を読むときは `getRouteApi`

`components/` は `routes/` を読まない。部品で URL のパラメータなどが要るときは、ルートのファイルを import せず、TanStack Router の `getRouteApi("/パス")` で取る。ルートのファイルを import すると、`routes/` → `components/` → `routes/` の輪ができる。
