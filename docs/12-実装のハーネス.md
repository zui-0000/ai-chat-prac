# 実装のハーネス

記録日: 2026-11-17 / 対象: Claude Code 2.1.325、Modern Web Guidance 1.0.1

Claude Code に FE を書かせるときに、このリポジトリの決まりを守らせるための仕組み。
決まりそのものは `docs/05`・`docs/06`・`docs/09` で決めてある。ここでは、それを Claude Code にどう読ませるかを決める。

## 決めたこと

| 何を                          | どうしたか                                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| どこでも要る決まり            | `CLAUDE.md` に書く（DB と API の名前、FE で使ってよいブラウザの機能）                                            |
| FE のファイルだけで要る決まり | `.claude/rules/` に書き、`paths` で読ませる（部品の置き方・見た目と UX・ルーティング）                           |
| `DESIGN.md`                   | `apps/web/DESIGN.md` に置き、`.claude/rules/ux.md` から読ませる。中身は見た目の方向性のチケット（ZSCM-36）で書く |
| 使ってよいブラウザの機能      | Baseline の Newly available。`CLAUDE.md` に書く                                                                  |
| Modern Web Guidance           | 自分のマシンに user スコープで入れる。このリポジトリには設定を書かない                                           |
| 1 日待ちの例外                | Modern Web Guidance の CLI（`npx -y modern-web-guidance@latest`）。`pnpm-workspace.yaml` のコメントに書く        |

## `CLAUDE.md` と `.claude/rules/` の分け方

| ファイル                             | いつ読まれるか                     |
| ------------------------------------ | ---------------------------------- |
| `CLAUDE.md`                          | 起動したとき、いつも               |
| `.claude/rules/*.md`（`paths` あり） | `paths` に合うファイルを触ったとき |

部品の置き方や UX のルールは、合わせて 200 行ほどある。`CLAUDE.md` に書くと、BE だけの作業でも毎回読まれる。
`paths` を付けた rules にすると、`apps/web/src/client/components/` などを触ったときだけ読まれる。

| ファイル                      | `paths`                             | 中身                                                                     |
| ----------------------------- | ----------------------------------- | ------------------------------------------------------------------------ |
| `.claude/rules/components.md` | `components/`・`styles/`・`assets/` | 置き場所・依存の向き・ファイルの形・export・Base UI・スタイル・Storybook |
| `.claude/rules/ux.md`         | `components/`・`styles/`            | `DESIGN.md` を読むこと、UX のルール、ダークパターンを作らない            |
| `.claude/rules/routing.md`    | `routes/`・`main.tsx`               | ファイルベースルーティングの決まり                                       |

- design-system-prac の rules を元にした。ファイル名（どこでも `index.tsx`）と export（パーツが複数なら `import * as`）は、`docs/06` で変えたので書き直した
- design-system-prac の部品ごとの使い方（確認ダイアログ・メニュー・Toast など）は移していない。このリポジトリにまだ部品が無いため。部品を作るチケットで、作った部品の分だけ足す
- 単体テストの決まりは、`CLAUDE.md` に同じことが書いてあるので移していない
- トークン・Storybook・Base UI はまだ入っていない（ZSCM-37・ZSCM-38 で入れる）。決まりは `docs/06` で決めてあるので、先に書いておく

## `DESIGN.md` は rules から読ませる

`docs/06` の「CLAUDE.md・AGENTS.md・DESIGN.md の違い」で残した、読ませ方の選び方。

| 読ませ方                             | 決めたか   | 理由                                                     |
| ------------------------------------ | ---------- | -------------------------------------------------------- |
| `CLAUDE.md` に `@apps/web/DESIGN.md` |            | BE だけの作業でも、毎回読まれる                          |
| **rules の `paths`**                 | これにした | 部品やスタイルを触れば、どのやり方で作り始めても読まれる |
| 部品を作るスキルの手順に書く         |            | スキルを使わずに部品を直したときに読まれない             |

置き場所はルートでなく `apps/web/` にした。見た目を持つのは `apps/web` だけで、`AGENTS.md` もそこにある。

## Baseline の目標を `CLAUDE.md` に書く

Modern Web Guidance は、何も言われないと Baseline の Widely available（主要ブラウザで 2 年半以上使えるもの）を前提にし、それより新しい機能には fallback を書く。
このリポジトリは Newly available（主要ブラウザの最新版で全部使えるもの）まで使うと決めたので、`CLAUDE.md` に書いて、要らない fallback を書かせない。
`apps/web` の外（BE）でも読まれるが、1 行なので `CLAUDE.md` に置いた。

## 後に回したもの

| 何を                                         | いつ                                    | 理由                                                                      |
| -------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------- |
| `@storybook/addon-mcp`                       | 土台（ZSCM-37）                         | Storybook がまだ無く、引ける部品もストーリーも無い                        |
| 部品を作るスキル                             | 土台・汎用の部品（ZSCM-37・ZSCM-38）    | 手順の中身（トークン・ストーリー・CSS Modules）がまだ無い                 |
| 役割ごとにモデルを分ける（サブエージェント） | Jira のチケットを進めるスキルを作るとき | 誰に何を渡すかは、そのスキルの流れで決まる                                |
| 書くたびに検査する hooks                     | 入れない                                | コミットのときに `vp staged`、PR で CI が回る。編集のたびに回すと遅くなる |
