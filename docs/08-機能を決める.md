# 機能を決める

記録日: 2026-11-15 / 状態: 決定

この AI チャットで何ができるか（機能）を決める。画面は `docs/05-画面を決める.md` で決めた。
ここでは何を作るかだけを決め、作るのは後続のチケットでやる。ここで決めた機能から、API（ZSCM-27）とチャットの部品（ZSCM-39）を決め、実装のチケットを切る。

- **最初の版**: 最初に使える形にするまでに作るもの
- **後で**: 最初の版には入れず、使ってみてから作るか決めるもの

操作と機能は、Claude や ChatGPT などの AI チャットと同じ形にそろえる。使う人が迷わず、作る側も手本を見ながら作れる。

## 会話

| 何         | 最初の版                                 | 後で                     |
| ---------- | ---------------------------------------- | ------------------------ |
| 会話の数   | 複数持ち、左の一覧で切り替える           |                          |
| 新しい会話 | `/` で最初のメッセージを送ったときに作る |                          |
| 会話の名前 | 最初のメッセージの先頭を名前にする       | AI が付ける・手で変える  |
| 会話を消す | 確認のダイアログを出してから消す         |                          |
| 一覧       | 新しく更新した順に並べる                 | ピン留め・検索・フォルダ |

- 新しい会話は、送ったときに作る。「新しい会話」を押したときに作ると、送らずに離れたときに空の会話が一覧に残る
- 名前を AI に付けさせると、返答とは別に AI を呼ぶことになる。まずは呼ばずに済む形にする
- 消すのは最初の版に入れる。試しの会話を片付けられるうえ、確認のダイアログ（Base UI）と、消したあとに一覧を更新する（TanStack Query）練習になる

## メッセージを送る

| 何                     | 最初の版                                       | 後で         |
| ---------------------- | ---------------------------------------------- | ------------ |
| 返答の出し方           | 少しずつ流しながら出す                         |              |
| 返答を止める           | 止めたところまでの返答は残して保存する         |              |
| 作り直す・直して送る   |                                                | どちらも後で |
| 送るキー               | Enter で送る。Shift+Enter で改行               |              |
| 送るのに失敗したとき   | エラーを出し、同じ内容を送り直せる             |              |
| 返答の途中             | 次は送れない。送るボタンが止めるボタンに変わる |              |
| 画像やファイルを付ける |                                                | 後で         |

- 日本語の変換を確定する Enter では送らない。忘れると、変換を確定しただけで送られる
- 作り直すと、Claude では前の返答も残り「1/2」と切り替えられる。会話が枝分かれする作りで、データの持ち方から変わるので、まずは 1 本道の会話にする
- 画像やファイルは、保存する場所（R2 など）と、モデルが対応しているかから決める必要がある

## 返答の表示

| 何             | 最初の版                                           | 後で                           |
| -------------- | -------------------------------------------------- | ------------------------------ |
| Markdown       | 見出し・箇条書き・表・コードを Markdown で出す     |                                |
| コードブロック | 枠に入れ、言語ごとに色を付け、コピーのボタンを置く |                                |
| 返答のコピー   | 返答の下に、返答全体をコピーするボタンを置く       |                                |
| 数式・図       |                                                    | KaTeX・Mermaid など            |
| 評価のボタン   |                                                    | 良い・悪いを集める先ができたら |

- 返答の中の HTML は、そのまま描かない。AI の返答に `<script>` や怪しいリンクが混ざっても、画面で動かないようにする（Generative UI をカタログ型にしたのと同じ考え方）
- 色付けのライブラリ（Shiki など）は重いものがあるので、バンドルの大きさを見て、部品のチケットで選ぶ

## Generative UI

| 何                   | 最初の版                                         | 後で                                             |
| -------------------- | ------------------------------------------------ | ------------------------------------------------ |
| 部品                 | 選択肢（押すとその内容で送る）と棒グラフ         | 天気・地図など外のデータを使うもの、入力フォーム |
| 部品を出す途中       | 形だけの枠を出し、props がそろったら部品に変える |                                                  |
| 会話を開き直したとき | 部品も保存しておき、同じ部品を出す               |                                                  |
| 選択肢を押したあと   | 押したものだけを残し、ほかは押せなくする         |                                                  |

- 選択肢は「押せる」部品、棒グラフは「見せる」部品。役割の違う 2 つで、画面から AI への行き来と、絵で見せることの両方を作る
- 表は Markdown の表で足りるので、部品にしない
- 外のデータを使う部品は、AI に外の API を呼ばせる仕組み（ツールの実行）まで要るので、後でやる

## AI

| 何               | 最初の版                                | 後で                         |
| ---------------- | --------------------------------------- | ---------------------------- |
| 使う AI          | Claude（Anthropic の API）              |                              |
| モデル           | Claude Opus 5.5。BE の設定 1 か所に書く | 使ってみて、料金を見て変える |
| モデルの切り替え |                                         | 設定の画面で切り替える       |

- Claude にしたのは、日本語と、ツールの使い方が強いから。Generative UI は、AI が決められた部品と props を正しく選べるかが要になる
- Void の `void/ai` からは、Workers AI（Llama など）や Gemini・GPT も呼べる。Workers AI はキーが要らず無料の枠もあるが、日本語とツールの使い方が弱め
- アプリからは、Claude Console で作った API キーで呼ぶ。キーは Void の秘密の値に入れる

### 料金

API の利用は、Claude の月額プラン（Max）とは別に課金される。ただし Max には、毎月 $100 分の API クレジットが付く（2026-11 時点）。

- claude.ai の請求の設定で、Claude Console の組織とつなぐともらえる（契約から 7 日たってから。つなげる組織は 1 つだけ）
- 繰り越さない。使い切ったら API が止まるだけで、勝手に課金されない（自動の追加購入を設定していなければ）
- 対話で使う Claude Code には使えない。アプリから Messages API を呼ぶ分に使える

| モデル            | 入力（100 万トークン） | 出力（100 万トークン） | 1 回あたり（入力 2,000・出力 1,000） | $100 で     |
| ----------------- | ---------------------- | ---------------------- | ------------------------------------ | ----------- |
| Claude Opus 5.5   | $4                     | $20                    | 約 $0.028                            | 約 3,500 回 |
| Claude Sonnet 5.5 | $2                     | $10                    | 約 $0.014                            | 約 7,000 回 |
| Claude Haiku 5.5  | $0.10                  | $0.50                  | 約 $0.0007                           | 約 14 万回  |

開発サーバーの画面はいつも偽物（MSW）と話すので、お金がかかるのは `preview` と、検品の環境だけ。検品の環境は自分だけが入れるようにして、学習に使う。会話が長くなると前のやりとりも毎回送るので、入力は増えていく。

## 認証・メール

| 何       | 最初の版                              | 後で                                             |
| -------- | ------------------------------------- | ------------------------------------------------ |
| ログイン | メールアドレスとパスワード、Google、X |                                                  |
| メール   |                                       | パスワードの再設定・メールアドレスの確認と一緒に |

- 認証は Void に組み込まれた Better Auth を使う。認証の API（`/api/auth`）は Void が出し、画面は自分で作る（`docs/05-画面を決める.md`）
- Google と X は、Void の設定（`auth.providers` に `google`・`twitter`）と、それぞれで登録したアプリの ID と秘密の値（`AUTH_GOOGLE_CLIENT_ID` など）で使える
- 実装のチケットは、メールアドレスとパスワード → Google と X の順に分ける。外の登録が要らないほうを先に作り、すぐ試せるようにする
- メールアドレスとパスワードも残す。外のサービスに頼らずにログインでき、テストもしやすい
- 最初の版に入れるのは、会話を最初から「誰のものか」付きで保存するため。後から持ち主を足すと、会話の DB と API を作り直すことになる
- Google と X のチケットで決めること: 同じ人がパスワードと Google の両方でログインしたときに 1 人として扱うか、X からメールアドレスを受け取れるか
- メールを使うのは、パスワードの再設定とメールアドレスの確認。どちらも最初の版ではやらない（`docs/05-画面を決める.md`）。入れるときに Cloudflare のメール（Void の Email）を確かめる

## 実装のチケット

最初の版の機能は、ストーリーにして、サブタスクで分ける。ブランチと PR はサブタスクごと。1 つの PR で見るものを絞り、レビューしやすくする。

| サブタスク | 中身                                         |
| ---------- | -------------------------------------------- |
| 契約       | `packages/contract` の約束                   |
| BE         | DB と API の実装                             |
| FE（UI）   | 画面の見た目と、Storybook のストーリー       |
| FE（機能） | 画面と API のつなぎ込み、偽物（MSW）、テスト |

| ストーリー                                           | サブタスク                     |
| ---------------------------------------------------- | ------------------------------ |
| ZSCM-41 メールアドレスとパスワードでログインできる   | BE・FE（UI）・FE（機能）       |
| ZSCM-42 Google と X でログインできる                 | 準備・BE・FE（UI）・FE（機能） |
| ZSCM-43 会話の一覧から会話を開き、消せる             | 契約・BE・FE（UI）・FE（機能） |
| ZSCM-44 メッセージを送り、返答を流しながら受け取れる | 契約・BE・FE（UI）・FE（機能） |
| ZSCM-45 返答の中に Generative UI の部品が出る        | 契約・BE・FE（UI）・FE（機能） |

- 認証の API（`/api/auth`）は Void が出し、oRPC の約束を使わないので、認証のストーリーには契約のサブタスクが無い
- Google と X は、各サービスでアプリを登録する「準備」から始める
- 部品そのもの（ZSCM-38〜40）は、ストーリーとは別のチケットで作る。ストーリーの FE（UI）は、その部品で画面を組む
- 検品の環境へのデプロイは、ZSCM-46 でやる
