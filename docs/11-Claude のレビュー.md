# Claude のレビュー

記録日: 2026-11-16 / 対象: claude-code-action 1.0.276、code-review プラグイン（claude-plugins-official）、actions/checkout 7.0.1

PR に `claude-review` のラベルを貼ると、GitHub Actions で Claude が PR をレビューし、指摘を PR のコメントにする。

## 決めたこと

| 何を                | どうしたか                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| ファイル            | `.github/workflows/claude-review.yaml`（ワークフローは `Claude Review`、ジョブは `review`）                  |
| 動くとき            | `claude-review` のラベルを貼ったとき（`pull_request` の `labeled`）。同じリポジトリのブランチの PR だけ      |
| Action              | Anthropic 公式の `anthropics/claude-code-action`。版はタグで書き、コミットは `actions.lock` で固定する       |
| レビューのやり方    | 公式の `code-review` プラグインを呼ぶ（`/code-review:code-review --comment`）                                |
| Claude の認証       | Max プランの OAuth トークン（`CLAUDE_CODE_OAUTH_TOKEN`）。Secrets に人が入れる                               |
| GitHub への書き込み | このジョブの `GITHUB_TOKEN`。Claude の GitHub App は入れない                                                 |
| 権限                | `contents: read` と `pull-requests: write` だけ                                                              |
| Claude が使える道具 | 行ごとのコメントを書く道具と、プラグインが決めた `gh` の読み取りとコメントだけ。コードを動かす道具は渡さない |
| マージの条件        | 入れない。レビューは参考の意見                                                                               |

## 動き方

1. PR に `claude-review` のラベルを貼る
2. Claude が差分と `CLAUDE.md` を読み、バグと `CLAUDE.md` の決まりに反するところを探す
3. 指摘は、その行へのコメントとして PR に付く。直し方の提案（suggestion）が付くこともある。指摘が無ければ「No issues found」のコメントが 1 つ付く

- 投稿者は `github-actions[bot]` になる（Claude の GitHub App ではなく `GITHUB_TOKEN` で書くため）
- 下書き・閉じた PR は飛ばす。Claude がもうコメントした PR も飛ばすので、ラベルを貼り直しても 2 回目は動かない（確かめた）

## レビューのやり方は公式のプラグイン

`code-review` プラグインは、Claude Code のチームが作った PR レビューの手順。手元の `/code-review` と同じもの。

- 小さいモデルで「レビューが要るか」を見て、複数のエージェントで別々に探し、見つけたものを別のエージェントで確かめ直してから出す
- 出すのは、確かなバグと、引用できる `CLAUDE.md` の違反だけ。好みの書き方や細かい指摘は出さない
- `CLAUDE.md` を読むので、決まりを書くほどレビューも効く

| 案                                | 決めたか   | 理由                                                                       |
| --------------------------------- | ---------- | -------------------------------------------------------------------------- |
| 自分でプロンプトを書く            |            | 何を見るか・誤検知をどう減らすかを、自分で作って直し続けることになる       |
| **公式の code-review プラグイン** | これにした | 誤検知を減らす手順が入っている。手元の `/code-review` と同じ基準で見られる |

### わざと間違えた PR で確かめた

試しの PR（#10、閉じた）に、次の 3 つを入れてラベルを貼った。3 つとも、その行へのコメントで指摘された。

| 入れた間違い                                   | 指摘                                                                              |
| ---------------------------------------------- | --------------------------------------------------------------------------------- |
| `if ((count = 0))`（比較のつもりの代入）       | 比較ではなく代入で、どの入力でも `"0 件"` になる。`===` に直す提案付き            |
| `items[items.length]`（添字が 1 つずれている） | いつも `undefined` になる。`items.length - 1` に直す提案付き                      |
| テストで `describe`・`it` を import している   | `CLAUDE.md` の「`describe`・`test`・`expect`・`vi` は import しない」を引いて指摘 |

1 回のレビューは、ジョブ全体で 30 秒ほど。

## 認証は Max の OAuth トークン

| 案                                              | 決めたか   | 理由                                                                                        |
| ----------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------- |
| API キー（`ANTHROPIC_API_KEY`）                 |            | 従量課金でお金がかかる。Max に付く毎月の API クレジットは、GitHub Action の実行には使えない |
| **OAuth トークン（`CLAUDE_CODE_OAUTH_TOKEN`）** | これにした | 追加のお金がかからない。公式の docs が Pro・Max の認証として案内している                    |

- Max の API クレジットのサポートの記事に、GitHub Action の実行は Claude Code の利用として扱われ、クレジットの対象外とある
- API クレジットは、アプリから Claude を呼ぶ分に使う（`docs/08-機能を決める.md`）。Action とは混ぜない
- 複数のリポジトリで共有する Secret には API キーを使う、と公式の docs にある。OAuth トークンは、作った人のプランに紐づくため。このリポジトリだけで使うので当てはまらない

**手放すもの**:

- 手元の Claude Code と同じ Max の利用枠を使う。ラベルを貼ったときだけ動かして、使う量を絞る
- トークンは 1 年で切れる。切れるとレビューが失敗するので、作り直して Secrets を入れ直す

### トークンの入れ方

```zsh
claude setup-token                     # トークンがターミナルに出る（1 年有効）
gh secret set CLAUDE_CODE_OAUTH_TOKEN  # 出たトークンを貼る
```

トークンは、チャットやファイルに貼らない。Secrets に入れたら、手元には残さない。

## 公開リポジトリで守ること

| 何を                   | どう守るか                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 誰が動かせるか         | ラベルを貼れるのは、リポジトリの triage 以上の権限を持つ人だけ（今は自分だけ）。Action も、動かした人の書き込み権限を確かめる |
| フォークの PR          | GitHub は秘密の値を渡さない。動いても失敗するだけなので、ジョブの `if` で同じリポジトリのブランチの PR だけにする             |
| `pull_request_target`  | 使わない。秘密の値を持ったまま、フォークの PR のコードを扱うことになる                                                        |
| `@claude` での呼び出し | コメントで動くワークフロー（`issue_comment` など）を置いていないので、誰が書いても動かない                                    |
| 権限                   | ワークフロー全体は `permissions: {}`。ジョブに `contents: read` と `pull-requests: write` だけを渡す                          |
| Claude の道具          | コードを動かす道具を渡さない。書き込み権限の無い人の PR では、Action が既定（`restrict_untrusted_prs`）でも止める             |
| ログ                   | `show_full_output` と `display_report` は使わない。ログは公開されるので、Claude のやりとりを全部は出さない                    |
| トークンの漏れ         | ログを `sk-ant` で探して、出ていないことを確かめた。`GITHUB_TOKEN` は `***` で伏せられる                                      |

- CodeQL の Actions の解析は、このワークフローに指摘 0 件
- `@claude` で呼べるワークフローを足すときは、`allowed_non_write_users` を使わない。書き込み権限の無い人の入力で Claude が動き、プロンプトの注入を受ける

### Claude の GitHub App を入れない

公式の手順では、Claude の GitHub App を入れて、App の名前でコメントする。ここでは入れずに、`github_token: ${{ secrets.GITHUB_TOKEN }}` を渡した。

- `GITHUB_TOKEN` は、ジョブで渡した権限（`pull-requests: write`）しか持たず、ジョブが終わると切れる
- App は、Contents・Issues・Pull requests の書き込みなど、もっと広い権限をリポジトリに持ち続ける
- App の認証に要る `id-token: write` も渡さずに済む

**手放すもの**: コメントの投稿者が Claude ではなく `github-actions[bot]` になる。

## まだ固定できていないもの

- **プラグインの中身**: `code-review` プラグインは、動くたびに claude-plugins-official の最新を取ってくる。Action は `actions.lock` で固定したが、プラグインは固定していない。中身が変わると、レビューの基準も変わる
- **レビューのやり直し**: Claude がもうコメントした PR は飛ばすので、直したあとにもう一度見てほしいときの手順はまだ決めていない（Claude のコメントを消してから貼り直せば動くかは、未確認）
