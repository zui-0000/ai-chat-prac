# 画面を決める

記録日: 2026-11-11 / 状態: 検討案 / 対象: Void 1.6.2、TanStack Router 1.170.46

この AI チャットに要る画面を、画面のレベルで洗い出した。
部品や見た目はデザインシステム（ZSCM-26）、API は API の設計（ZSCM-27）で決める。

## 画面の一覧

| 画面     | パス              | 優先度 | ログイン |
| -------- | ----------------- | ------ | -------- |
| チャット | `/`・`/chats/:id` | must   | 要る     |
| ログイン | `/login`          | must   | 要らない |
| 新規登録 | `/signup`         | must   | 要らない |
| 設定     | `/settings`       | want   | 要る     |

今ある `/about` は雛形の名残なので、消す。

## 画面ごとの役割

### チャット

AI と話す画面。

- 左: 会話の一覧（新しい会話を始める・過去の会話に切り替える）
- 右: メッセージの一覧と入力欄。AI の返答は少しずつ流れて表示される
- `/` は新しい会話、`/chats/:id` は過去の会話を開く
- 設定への入口とログアウトも、ここに置く

会話の一覧は別の画面にせず、チャット画面の一部にする。
切り替えるたびに画面を移るより、横に並べたほうが使いやすいため。

### ログイン・新規登録

メールアドレスとパスワードで、ログインまたは新規登録する画面。

- 成功したら `/` に移る
- 2 つの画面は互いにリンクで行き来できる

### 設定（want）

ログインしている人が、自分の設定を変える画面。

- 表示名を変える
- テーマ（ライト・ダーク）を切り替える
- 使う AI のモデルを選ぶ（さらに余裕があれば）

## ログインは画面か、機能か

**両方**。仕組みは Void が持っていて、画面は自分で作る。

| 何                     | 誰が作るか                                                                  |
| ---------------------- | --------------------------------------------------------------------------- |
| ログインの仕組み       | Void。Better Auth を組み込んでいて、API（`/api/auth`）とクライアントを出す  |
| ログイン・新規登録画面 | 自分。Void は画面を出さない                                                 |
| 未ログインを止める     | 自分。画面ではなく、ルートの仕組み（TanStack Router の `beforeLoad`）で作る |

未ログインでチャットや設定を開くと、`/login` に移す。

## 画面の移り方

```text
/login ⇄ /signup
   │ 成功
   ↓
チャット（/・/chats/:id） ⇄ /settings
   │ ログアウト（設定からもできる）
   ↓
/login
```

## 決めたいこと

推奨を太字にした。

**1. 会話を複数持つか**

| 案                         | 良いところ                            | 手放すもの           |
| -------------------------- | ------------------------------------- | -------------------- |
| **複数（一覧で切り替え）** | AI チャットの基本の形。学ぶ題材が多い | 画面と API が増える  |
| 1 つだけ                   | 作るものが少ない                      | 過去の会話に戻れない |

**2. ログインと新規登録を分けるか**

| 案                                  | 良いところ                                             | 手放すもの               |
| ----------------------------------- | ------------------------------------------------------ | ------------------------ |
| **別の画面（`/login`・`/signup`）** | 入力欄が違う（新規登録は名前も要る）。URL で直接開ける | 画面が 1 つ増える        |
| 1 つの画面でタブを切り替える        | 画面が 1 つで済む                                      | 1 つの画面の状態が増える |

**3. ログインしないで使えるか**

| 案                         | 良いところ                                    | 手放すもの                 |
| -------------------------- | --------------------------------------------- | -------------------------- |
| **使えない（要ログイン）** | 会話を人ごとに保存できる。AI の利用料を守れる | 試すのに登録が要る         |
| 使える（ゲスト）           | すぐ試せる                                    | 会話の持ち主の扱いが増える |

## 今回はやらない

- パスワードの再設定、メールアドレスの確認（メールを送る仕組みが要る）
- Google・GitHub などのソーシャルログイン
- アカウントの削除

## 実装で気をつけること

- 開発サーバーの画面は、いつも偽物（MSW）と話す（`docs/04-MSW.md`）。
  ログインの API は `/rpc` ではなく `/api/auth` なので、偽物にも別に用意が要る
- 404 やエラーの表示は、画面ではなくルートの共通の表示（TanStack Router の `notFoundComponent`・`errorComponent`）で作る
