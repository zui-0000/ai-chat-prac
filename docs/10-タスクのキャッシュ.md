# タスクのキャッシュ

記録日: 2026-11-16 / 対象: Vite+ 1.6.0、Void 1.6.2、actions/cache 6.1.0

`vp run` で回す検査・テスト・ビルドに Vite Task のキャッシュを効かせ、変わっていないものを飛ばす。手元でも CI でも使う。

Vite Task は、タスクが実際に読んだファイルを記録し、それが変わったときだけ回し直す。「client の差分なら client のテスト、`packages/contract` の差分なら両方」のような一覧を、人が書かずに済む（`docs/07-CI.md` の「テストは毎回全部回す」）。

## 決めたこと

| 何を                      | どうしたか                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------ |
| キャッシュするもの        | `build`・`typecheck`・`lint:deps`・`test`・`test:client`・`test:server`                          |
| 書く場所                  | `package.json` のスクリプトから、各パッケージの `vite.config.ts` の `run.tasks` に移した         |
| キャッシュしないもの      | `dev`・`preview`・`db:generate`（スクリプトのまま）。`vp check` は `vp run` を通らないので対象外 |
| `run.tasks` の書き方      | 変数を使わず、値をそのまま書く                                                                   |
| Void の実行状態           | `apps/web/.void/v3` を、`vp build`・`vp test` のタスクの入力と出力から外す                       |
| CI でキャッシュを戻す     | PR のときだけ。前の実行のキャッシュを `actions/cache` で戻す                                     |
| CI でキャッシュを保存する | 毎回（main も PR も）。どれかが落ちても保存する                                                  |
| main に入ったとき         | キャッシュを戻さず、いつも全部回す                                                               |
| キャッシュのキー          | OS・CPU・実行ごとの番号だけ。lockfile などは入れない                                             |
| Turborepo                 | 入れない。`vp run` とタスクを回す道具が 2 つになる                                               |

npm で言えば、Turborepo や Nx のキャッシュを `vp run` が持っている形。違うのは、入力のファイルを `inputs` に書かなくても、読んだファイルを自分で記録すること。

## スクリプトをタスクに移した

`package.json` のスクリプトは、既定でキャッシュされない（`vp run` が「cache disabled」と出す）。`vite.config.ts` の `run.tasks` に書いたタスクは、既定でキャッシュされる。

| 案                            | 決めたか   | 理由                                                                                                                 |
| ----------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| ルートで `run.cache: true`    |            | スクリプトを全部キャッシュする。`dev` のような止めるまで動き続けるものまで対象になる。タスクごとに入力も変えられない |
| **`vite.config.ts` のタスク** | これにした | キャッシュするものを選べる。Void の実行状態を外すなど、タスクごとに設定できる                                        |

- タスクとスクリプトに同じ名前は付けられないので、移したものは `package.json` から消した
- ルートの `package.json` のスクリプト（`vp run web#test` など）はそのまま。`vp run` は、中の `vp run` をタスクとして展開してキャッシュする
- `packages/contract` には `typecheck` のためだけに `vite.config.ts` を置いた

### 前は「キャッシュしない」と決めていた

雛形を作ったとき（`docs/01-構成を決める.md` の 6）は、`run.cache: true` を消した。TypeScript 7 の `tsc` は Go で書かれていて、ファイルの読み込みを Vite Task が追えず、型エラーを見逃したため。

今の型チェックは tsrs（Rust）で、読み込みを追える。わざと型を壊したとき・新しいファイルを足したとき・依存の中身を変えたときに、回し直されることを確かめた。`tsc` に戻すときは、`typecheck` を `cache: false` にする（`apps/web/vite.config.ts` のコメント）。

## `run.tasks` は値だけで書く

`run.tasks` に変数を使うと、`vp run` がルートに `.void/` を作るようになった。

- `vp run` は、各パッケージの `vite.config.ts` からタスクを探す。`run` の中が値だけなら、設定を実行せずに文字として読む。変数が混ざると、設定を実行して読む
- 設定を実行すると、`voidPlugin()` が呼ばれる。Void の plugin は、呼ばれたその場で `process.cwd()`（ルート）を自分のアプリとみなし、`.void/` を書く（`docs/02-単体テスト.md` と同じ原因）
- 同じ `cache` の設定を 4 か所に書くことになるが、変数にまとめない

小さな雛形で、値だけのときは設定が実行されず、変数を混ぜると実行されることを確かめた。

## Void の実行状態を入力から外す

外さないと、関係ない変更でもテストとビルドのキャッシュが外れた。

```text
vp test --project server ○ cache miss: 'apps/web/.void/v3/observability/miniflare-wobs-trace-store/....sqlite-wal' modified, executing
```

`.void/v3` は、Void の plugin が読み書きするローカルの実行状態（miniflare の DB など）。動かすたびに書き換わる。

```ts
cache: {
  input: [{ auto: true }, "!.void/v3/**"],
  output: [{ auto: true }, "!.void/v3/**"],
},
```

- `{ auto: true }` で、読んだファイルの記録はそのまま使い、`.void/v3` だけを外す
- 出力からも外す。キャッシュから戻すときに、ローカルの DB を古い中身で上書きしないため

## 何を変えると、何が回し直されるか

手元で、ファイルの末尾に 1 行足して確かめた。

| 変えたもの                          | `typecheck`         | `lint:deps`  | `test:client` | `test:server` | `build` |
| ----------------------------------- | ------------------- | ------------ | ------------- | ------------- | ------- |
| `packages/contract`                 | 回す                | 飛ばす       | 回す          | 飛ばす（※1）  | 回す    |
| `src/client/main.tsx`               | 回す（app だけ）    | 回す         | 飛ばす（※2）  | 飛ばす        | 回す    |
| `src/server/db/schema.ts`           | 回す（app と test） | 回す         | 回す（※3）    | 回す          | 回す    |
| `apps/web/vite.config.ts`           | 回す（app だけ）    | 飛ばす       | 回す          | 回す          | 回す    |
| 依存の中身（zod の `package.json`） | 回す                | 飛ばす（※4） | 回す          | 回す          | 回す    |

- ※1 今の server のテストは環境を確かめる 1 本だけで、約束を読まない。約束を読むテスト（`#/server/rpc/router.ts` を import する）を一時的に置くと、回し直された
- ※2 client のテストは `main.tsx` を読まない。読んでいないファイルの変更では回さない
- ※3 Void の plugin が設定を読み込むときに `src/server` を読むので、server の変更で client のテストも回る
- ※4 dependency-cruiser は `src` の import の向きだけを見て、zod の中は読まない
- 依存の中身は、ストアのファイルを壊さないように、ハードリンクを外してから書き換えて確かめた
- 依存を上げると、`node_modules/.pnpm/<名前>@<版>/` の場所ごと変わるので、読んだファイルが変わって回し直される。`pnpm-lock.yaml` をキーに入れなくてよい

**手放すもの**: 何を読んだかで決まるので、「このテストは回るはず」と思っても飛ばされることがある（※1・※2）。飛ばされるのは、そのテストが読んでいないファイルを変えたときだけ。

## CI でキャッシュを使い回す

Vite Task のキャッシュは `node_modules/.vite/task-cache` にある。CI では毎回新しいマシンで動くので、`actions/cache` で前の実行から戻す。Vite+ 1.6.0 では試験的な機能なので、入れる前と後の時間を測った。

```yaml
- name: Vite Task のキャッシュを戻す
  if: ${{ github.event_name == 'pull_request' }}
  uses: actions/cache/restore@v6.1.0
  with:
    path: node_modules/.vite/task-cache
    key: vite-task-${{ runner.os }}-${{ runner.arch }}-${{ github.run_id }}-${{ github.run_attempt }}
    restore-keys: |
      vite-task-${{ runner.os }}-${{ runner.arch }}-
```

- 戻すのは install のあと。install が `node_modules` を作り直すため
- GitHub のキャッシュは上書きできないので、キーに実行ごとの番号を入れ、`restore-keys` でいちばん新しいものを戻す
- キーに lockfile やソースを入れない。入れると、少し変えただけで何も戻らなくなる。何が変わったかは Vite Task が中身を見て決める
- キャッシュに入るのは成功したタスクだけ（終了コード 0）。落ちたタスクは次も回るので、どれかが落ちても保存する
- ファイルの更新日時ではなく中身で比べるので、checkout し直した CI のマシンでもキャッシュが当たった

### main では戻さない

main に入ったときは、キャッシュを戻さずに全部回し、その結果を保存する。

- main の結果は、キャッシュに頼らずに出したものになる。万一キャッシュが間違っていても、main で気づける
- PR は、自分のブランチと main のキャッシュを戻せる（GitHub のキャッシュの範囲）。main で保存したものが、新しい PR の最初の実行で使われる
- PR で保存したキャッシュは、その PR からしか戻せない。PR のキャッシュが main に入り込むことはない

### 入れる前と後の時間

ジョブ全体と、キャッシュが効くステップ（型チェック・import の向き・テスト 2 つ・ビルド）の合計。どれも ubuntu-latest。

| 実行                                           | ジョブ全体 | キャッシュが効くステップ | キャッシュを戻す・保存する |
| ---------------------------------------------- | ---------- | ------------------------ | -------------------------- |
| 入れる前（main、PR #7 のマージ）               | 31 秒      | 11 秒                    | —                          |
| 入れる前（PR #7）                              | 40 秒      | 14 秒                    | —                          |
| 入れた後・キャッシュなし（この PR の最初）     | 47 秒      | 15 秒                    | 3 秒                       |
| 入れた後・全部当たった（同じコミットの再実行） | 33 秒      | 0 秒                     | 3 秒                       |
| 入れた後・docs だけ変えた（次のコミット）      | 31 秒      | 0 秒                     | 3 秒                       |

- docs・`CLAUDE.md`・`README.md` はどのタスクも読まないので、変えても全部当たる。ふだんの PR でよくある形
- 全部当たると、キャッシュが効くステップの 11〜15 秒が 0 秒になり、戻す・保存するで 3 秒増える。差し引き 10 秒ほど速い
- ジョブ全体の時間は、`setup-vp`（Node.js・pnpm・install）の 13〜19 秒で上下する。キャッシュの効き目より、この揺れのほうが大きいこともある
- GitHub に保存されたキャッシュは 1 回 1.3 MB ほど（圧縮後。手元の `task-cache` は 8.4 MB）。実行ごとに増えるが、GitHub のキャッシュの上限（リポジトリで 10 GB）には遠く、使われないものは GitHub が消す

効き目は小さいが、テストやビルドが増えるほど大きくなる。戻す・保存するの 3 秒は増えないので、残す。

**手放すもの**: キャッシュが外れたときは、戻す・保存するの 3 秒だけ遅くなる。Vite Task はタスクごとに古いキャッシュを消さないので、`task-cache` は少しずつ大きくなる。大きくなりすぎたら、GitHub のキャッシュを消せば作り直される。

## 困ったとき

```zsh
vp run --last-details   # 直前の vp run で、それぞれのタスクが当たったか・外れた理由
vp run --no-cache test  # キャッシュを使わずに回す
vp cache clean          # 手元のキャッシュ（node_modules/.vite/task-cache）を消す
```
